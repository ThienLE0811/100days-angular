Bản Chất ngModel: Giải Mã Cú Pháp "Banana-in-a-box" [()]

Ví dụ Tiep Phan từ Tài liệu
💡
Bản chất viết tắt của [(ngModel)]="name": Cú pháp hình "trái chuối trong hộp" [()] thực chất là sự kết hợp của:
1. [ngModel]="name" (Property Binding: Dữ liệu từ component đổ xuống thẻ input).
2. (ngModelChange)="name = $event" (Event Binding: Khi người dùng gõ phím, sự kiện phát ra giá trị mới và gán ngược lại cho biến).

🎮 Thử Nghiệm: Đối Chiếu Cú Pháp Viết Tắt vs Phân Rã

Cả 2 ô nhập liệu bên dưới đều thao tác trực tiếp trên cùng 1 biến userName. Hãy gõ thử ở bất kỳ ô nào:

Cách 1: Cú pháp viết tắt [(ngModel)]
<input [(ngModel)]="userName" />
Cách 2: Cú pháp phân rã [ngModel] + (ngModelChange)
<input [ngModel]="userName" (ngModelChange)="name = $event" />

Điều Khiển Từ Phía Component Cha:
Bí Quyết Viết Component Con TypeScript 
// Trong toggle.component.ts:
@Component({
  selector: 'app-toggle',
  template: `<div class="toggle-wrapper" [class.checked]="checked" (click)="toggle()">...</div>`
})
export class ToggleComponent {
  // 1. Input nhận dữ liệu vào
  @Input() checked = false;

  // 2. Output BẮT BUỘC có hậu tố "Change": checked + Change
  @Output() checkedChange = new EventEmitter<boolean>();

  toggle() {
    this.checked = !this.checked;
    // 3. Phát giá trị mới ra cha
    this.checkedChange.emit(this.checked);
  }
}

<!-- Trong app.component.html (Cha sử dụng 2 chiều): -->
<app-toggle [(checked)]="toggleState"></app-toggle>
Ghi nhớ: Nếu bạn đặt tên output là onChecked hay checkedEvent, Angular sẽ không thể nhận diện cú pháp [(checked)]! Bắt buộc phải là checkedChange.

Định Nghĩa Stepper Two-Way TypeScript 
// Trong number-stepper.component.ts:
@Component({ selector: 'app-number-stepper', ... })
export class NumberStepperComponent {
  @Input() count = 0;
  @Output() countChange = new EventEmitter<number>();

  increment() {
    this.count++;
    this.countChange.emit(this.count);
  }
  decrement() {
    this.count--;
    this.countChange.emit(this.count);
  }
}

<!-- Sử dụng tại component cha: -->
<app-number-stepper [(count)]="quantity"></app-number-stepper>

Tiến Hóa: Classic @Input/@Output Change vs Angular 19 model() Signal

So sánh kiến trúc truyền thống và hiện đại
🚀
Bước tiến hóa lớn từ Angular 17.2+: Nếu như ở Day 9, chúng ta phải viết 2 dòng (@Input() value và @Output() valueChange), thì Angular hiện đại cung cấp hàm model(). Khi khai báo value = model(0), Angular tự động cấu hình cả Input lẫn Output ngầm định mà vẫn giữ nguyên cú pháp [(value)]="parentVar" ở phía ngoài!
Tiêu Chí So Sánh Cách Tiếp Cận Cổ Điển (Day 9) Cách Tiếp Cận Hiện Đại (Angular 19+)
Cú pháp khai báo @Input() checked = false;
@Output() checkedChange = new EventEmitter(); 		readonly checked = model(false);
Cập nhật giá trị this.checked = newVal;
this.checkedChange.emit(this.checked); 		this.checked.set(newVal); hoặc
this.checked.update(v => !v);
Tương thích Signal / Computed Phải chuyển đổi qua toSignal() Là WritableSignal sẵn có
Cú pháp dùng ở Cha [(checked)]="state" Giữ nguyên 100% [(checked)]="state"
