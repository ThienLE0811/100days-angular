Cú Pháp exportAs: #varName="exportAsOfDirective"

Ví dụ Form Validation từ Tài liệu
📋
Tại sao cần exportAs? Khi một thẻ HTML gắn nhiều directive (ví dụ thẻ <form> có gắn NgForm, thẻ <input> có gắn NgModel), nếu chỉ viết #f, Angular sẽ mặc định trả về thẻ HTMLFormElement. Để lấy về chính xác đối tượng directive NgForm nhằm kiểm tra tính hợp lệ (validation), bạn dùng cú pháp: #f="ngForm" và #ctrl="ngModel".

Phần 3

@ViewChild Trong Class: static: true/false & read: ElementRef

Điều khiển từ TypeScript Class
🔍
Khi nào dùng @ViewChild? Khi bạn cần gọi method của component con bên trong mã lệnh TypeScript của component cha (chứ không phải ngoài template), bạn dùng @ViewChild('templateVarName').
• static: true: Khởi tạo trước Change Detection, có sẵn ngay trong ngOnInit().
• static: false (mặc định): Chỉ sẵn sàng sau khi DOM hoàn tất render trong ngAfterViewInit().
• read: ElementRef: Đọc thẻ DOM native thay vì instance class của Component.

Cú Pháp @ViewChild & Options TypeScript 
export class AppComponent implements OnInit, AfterViewInit {
  // 1. static: true -> Truy cập an toàn trong ngOnInit()
  @ViewChild('staticInput', { static: true })
  inputRef!: ElementRef<HTMLInputElement>;

  // 2. Truy vấn Component instance (mặc định static: false)
  @ViewChild('singleToggle')
  toggleComp!: AppToggleItemComponent;

  // 3. read: ElementRef -> Lấy native DOM của component
  @ViewChild('singleToggle', { read: ElementRef })
  toggleNativeEl!: ElementRef<HTMLElement>;

  ngOnInit() {
    // inputRef đã sẵn sàng tại đây!
  }

  ngAfterViewInit() {
    // toggleComp đã sẵn sàng tại đây!
    this.toggleComp.turnOn();
  }
}
Cạm bẫy thường gặp (Gotcha): Đừng bao giờ truy cập @ViewChild có static: false trong ngOnInit(), vì tại thời điểm đó Angular chưa render xong DOM con, giá trị sẽ bị undefined!

@ViewChildren & QueryList: Thao Tác Danh Sách Hàng Loạt

Quản lý nhiều Component cùng loại
🗂️
Khi nào dùng @ViewChildren? Khi bạn render một danh sách nhiều component (ví dụ qua @for), @ViewChildren(ComponentType) sẽ gom toàn bộ các instance vào một đối tượng QueryList. QueryList hỗ trợ các hàm lặp như .forEach(), .map(), .filter() và phát ra Observable .changes mỗi khi có phần tử được thêm hoặc xóa khỏi DOM.

🎮 Thao Tác Hàng Loạt Với QueryList

Kích Hoạt Sự Kiện QueryList.changes (Thêm/Bớt phần tử):
Cú Pháp @ViewChildren & QueryList TypeScript 
@Component({ ... })
export class DashboardComponent implements AfterViewInit {
  // Truy vấn toàn bộ các instance của AppToggleItemComponent
  @ViewChildren(AppToggleItemComponent)
  toggleList!: QueryList<AppToggleItemComponent>;

  ngAfterViewInit() {
    // Lắng nghe khi số lượng phần tử thay đổi:
    this.toggleList.changes.subscribe(() => {
      console.log('Số lượng hiện tại:', this.toggleList.length);
    });
  }

  // Bật toàn bộ bằng cách lặp qua QueryList:
  turnAllOn() {
    this.toggleList.forEach(comp => comp.turnOn());
  }
}
Điểm đặc biệt của QueryList: Không giống như mảng thông thường (Array), QueryList là một Observable collection tự động cập nhật khi DOM thay đổi, không cần phải tự query lại thủ công!

Tiến Hóa: Decorator Queries vs Angular 19 Signal Queries

viewChild() & viewChildren()
🚀
Bước nhảy vọt từ Angular 17.2+: Angular giới thiệu các hàm truy vấn dạng Signal: viewChild() và viewChildren(). Chúng thay thế các decorator @ViewChild cổ điển, trả về một Signal có thể dùng trực tiếp trong computed() hoặc template mà không cần chờ đợi phức tạp ở ngAfterViewInit()!
