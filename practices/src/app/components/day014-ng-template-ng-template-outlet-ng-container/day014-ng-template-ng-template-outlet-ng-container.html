ngTemplateOutlet & ngTemplateOutletContext (Truyền Dữ Liệu Vào Template)

Parameterization
⚙️
Giống như component nhận @Input(), <ng-template> nhận dữ liệu thông qua ngTemplateOutletContext:
  • Explicit (Tường minh): let-myVar="keyInContext" → Truy cập biến {{ '{{' }} myVar {{ '}}' }} tương ứng giá trị của property keyInContext trong object.
  • Implicit (Ngầm định): let-defaultVar (không có dấu =) → Tự động ánh xạ với giá trị của property đặc biệt $implicit.

Pattern thư viện UI
🧩
Kỹ thuật chuyên sâu: Các UI Framework nổi tiếng (như Angular Material, NG-ZORRO, PrimeNG) đều sử dụng mô hình này. Component con cung cấp một template header mặc định, nhưng nhận thêm @Input() headerTemplate?: TemplateRef<any>. Nếu component cha truyền vào template tùy chỉnh, nó sẽ ghi đè (override) template mặc định mà không cần sửa code của component con!

📖 Tóm Tắt So Sánh: ng-template, ngTemplateOutlet và ng-container

Khái Niệm Bản Chất Kỹ Thuật Có Sinh Thẻ DOM Thật? Trường Hợp Dùng Tiêu Biểu Lưu Ý Quan Trọng
<ng-template> Là một TemplateRef chứa khung HTML mẫu trong bộ nhớ. ❌ Không sinh thẻ (chỉ xuất hiện khi render) Dùng trong *ngIf else, tách khối UI tái sử dụng, truyền template vào con. HTML bên trong không bao giờ tự hiển thị ở vị trí định nghĩa. Biến bên trong không có strict type-check.
ngTemplateOutlet Chỉ thị (Directive) chịu trách nhiệm lấy TemplateRef để cắm vào DOM. Phụ thuộc thẻ chứa nó (thường đi kèm <ng-container> để zero-tag) Render động các template, truyền data qua ngTemplateOutletContext. Cần truyền $implicit cho biến không tên, hoặc let-key="key" cho biến tường minh.
<ng-container> Thẻ nhóm ảo (Virtual Grouping Element) do Angular cung cấp. ❌ Không sinh thẻ (biến mất hoàn toàn khi render) Gom nhóm để gán directive (*ngIf, *ngFor, ngTemplateOutlet), tránh phá Flex/Grid. Tuyệt đối không gán class CSS trực tiếp lên ng-container vì nó không tồn tại trên DOM!
